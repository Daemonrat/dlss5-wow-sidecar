# Experimental RTX 20 and RTX 30 support

This fork removes the manager and runtime architecture refusals for RTX 20 and
RTX 30 cards. Their identities remain Turing and Ampere; they are not spoofed
as Ada or Blackwell. GTX cards that share Turing device-id ranges stay refused.

The GPU check is a warning on these cards. A known runtime is no longer rejected
solely because the GPU is Turing or Ampere, but the warning explains that its
kernels must match the card. NGX capability checks, guarded feature creation and
evaluation, and passthrough fallback remain in place. Existing Ada/Blackwell
runtime mismatch checks remain in place.

## Runtime setup

The upstream release bundles an Ada-patched `nvngx_dlssnr.dll`. Removing a
startup check does not add Turing or Ampere CUDA kernels to that DLL. Supply a
community runtime built for your GPU, or patch an original runtime locally.

One option is [dev-camo/dlssnr-patcher](https://github.com/dev-camo/dlssnr-patcher)
at commit `98dac112990e5cea30ab03d74625fc848bce5c92`. It requires Python 3.10+
and CUDA Toolkit 13.3 with `ptxas`, `fatbinary` and `cuobjdump` on PATH.
The patcher is GPL-2.0 and is run separately; its code is not vendored here.

From a separate working folder:

```powershell
git clone https://github.com/dev-camo/dlssnr-patcher
git -C dlssnr-patcher checkout 98dac112990e5cea30ab03d74625fc848bce5c92
python .\dlssnr-patcher\dlssnr_patcher.py "D:\original\nvngx_dlssnr.dll" --turing --ampere --ada --blackwell --output "D:\patched\nvngx_dlssnr.dll"
```

Use actual paths on your machine. The output parent directory must exist.
The separate output preserves the original DLL. A successful patch does not
establish that neural rendering works with this sidecar on your card.

Copy the patched `nvngx_dlssnr.dll` next to `wowsidecar.exe`, alongside
`nvngx_dlss.dll`, the ReShade proxy `dxgi.dll` and
`renodx-dlss5.addon64`. These belong in the sidecar folder, outside the WoW folder.
The manager may show an unknown-digest warning for your new runtime; this is
expected. The sidecar tries it and preserves NGX failures in `sidecar.log`.

Turing uses optical flow grid 4 even if a preset requests grid 1 or 2.
Ampere retains the requested grid. There is no measured resolution ceiling for
RTX 20/30, so this fork does not invent one or silently downscale the capture.

## Build

```powershell
cmake -S . -B build -A x64 -DSIDECAR_REQUIRE_SDKS=ON -DDLSS_SDK_DIR="D:\SDKs\DLSS" -DNVOF_SDK_DIR="D:\SDKs\Optical-Flow-SDK"
cmake --build build --config Release
.\build\tests\Release\sidecar_tests.exe "[unit]"
```

Both SDKs are required for a useful neural build. Default SDK-free CI builds
test the unit logic but cannot produce a functioning neural pipeline.
The fork does not redistribute patched NVIDIA binaries.

## Hardware validation

No RTX 20/30 device validation has been performed for this change.

Use the manager's Off preset to establish capture and overlay operation, then
compare against Recommended. Inspect `sidecar.log` together with
`ReShade.log` for the add-on's own neural feature creation/evaluation result.
An ordinary DLSS/DLAA feature being created, a running overlay or a stable frame
rate does not prove that the add-on produced neural-rendered output.

Record GPU model, driver version, runtime SHA-256, capture dimensions,
capture/overlay FPS and latency alongside the A/B result.
